# 08 — 事务管理与乐观更新

## 8.1 设计目标

桌面应用的用户期望即时响应，不能像 Web 应用那样等待服务端返回。MirageInk 采用**乐观更新 + 事务兜底**的双轨策略：

```
用户操作 → 立即更新 UI（乐观）
  ↕ invoke
Rust 事务执行 → 成功 / 失败
  ↕ emit
成功 → 确认 UI
失败 → 回滚 UI + 提示
```

## 8.2 分层责任

| 层        | 职责                      | 工具                    |
| --------- | ------------------------- | ----------------------- |
| 前端 View | 触发操作、防重复提交      | Button loading state    |
| ViewModel | 乐观更新、快照保存、回滚  | RTK Immer + extraReducers |
| Rust UseCase | 业务编排、事务边界    | rusqlite Transaction    |
| SQLite    | 事务原子性、持久化        | BEGIN/COMMIT/ROLLBACK   |
| Event     | 成功/失败通知             | emit success / rollback |

## 8.3 前端乐观更新实现

### 8.3.1 ViewModel 快照

```typescript
// view-models/articleEditorSlice.ts
interface ArticleEditorState {
  article: ArticleDTO | null;
  isDirty: boolean;
  saveStatus: 'idle' | 'saving' | 'succeeded' | 'failed' | 'conflict';
  // 乐观更新前的快照，用于回滚
  snapshot: ArticleDTO | null;
}

const articleEditorSlice = createSlice({
  name: 'articleEditor',
  initialState,
  reducers: {
    // 本地编辑：乐观更新 content
    updateContent(state, action: PayloadAction<string>) {
      if (state.article) {
        // 首次编辑时保存快照
        if (!state.snapshot) {
          state.snapshot = { ...state.article };
        }
        state.article.content = action.payload;
        state.isDirty = true;
        state.article.version += 1;  // 乐观递增版本号
      }
    },

    // 保存成功后清除快照
    saveSucceeded(state, action: PayloadAction<ArticleDTO>) {
      state.article = action.payload;
      state.snapshot = null;
      state.isDirty = false;
      state.saveStatus = 'succeeded';
    },

    // 保存失败：回滚到快照
    saveFailed(state) {
      if (state.snapshot) {
        state.article = state.snapshot;
        state.snapshot = null;
      }
      state.isDirty = true;  // 未保存的内容还在 UI
      state.saveStatus = 'failed';
    },

    // 服务端版本冲突
    saveConflict(state, action: PayloadAction<{
      serverArticle: ArticleDTO;
      localSnapshot: ArticleDTO;
    }>) {
      state.article = action.payload.serverArticle;
      state.snapshot = action.payload.localSnapshot;
      state.saveStatus = 'conflict';
    },
  },
});
```

### 8.3.2 Async Thunk 乐观保存

```typescript
export const saveArticle = createAsyncThunk(
  'articleEditor/save',
  async (_, { getState, dispatch, rejectWithValue }) => {
    const state = getState() as RootState;
    const { article } = state.articleEditor;
    if (!article) return rejectWithValue('No article');

    try {
      const result = await invoke<ArticleDTO>('article:update', {
        id: article.id,
        content: article.content,
        clientVersion: article.version - 1, // 服务端版本 = 乐观递增前的版本
      });
      dispatch(saveSucceeded(result));
      return result;
    } catch (error: any) {
      if (error.code === 'VERSION_CONFLICT') {
        dispatch(saveConflict({
          serverArticle: error.serverArticle,
          localSnapshot: state.articleEditor.snapshot!,
        }));
      } else {
        dispatch(saveFailed());
      }
      return rejectWithValue(error);
    }
  }
);
```

### 8.3.3 防重复提交

```typescript
// hooks/useSaveWithDebounce.ts
export function useSaveWithDebounce(delay = 2000) {
  const dispatch = useDispatch();
  const saveStatus = useSelector(selectSaveStatus);
  const isDirty = useSelector(selectIsDirty);

  const triggerSave = useCallback(() => {
    if (saveStatus === 'saving') return; // 正在保存，忽略
    if (!isDirty) return;                // 无变更，忽略
    dispatch(saveArticle());
  }, [saveStatus, isDirty, dispatch]);

  // 自动保存：每 2s 无操作时触发
  useEffect(() => {
    const timer = setTimeout(triggerSave, delay);
    return () => clearTimeout(timer);
  }, [triggerSave, delay]);

  return { triggerSave, saveStatus };
}
```

## 8.4 Rust 侧事务管理

### 8.4.1 事务包装器

```rust
// infrastructure/transaction.rs
use rusqlite::{Connection, TransactionBehavior};

pub struct Transaction<'a> {
    conn: &'a Connection,
    committed: bool,
}

impl<'a> Transaction<'a> {
    pub fn begin(conn: &'a Connection) -> Result<Self, AppError> {
        conn.execute("BEGIN IMMEDIATE", [])
            .map_err(|e| AppError::Database(e.to_string()))?;
        Ok(Self { conn, committed: false })
    }

    pub fn commit(mut self) -> Result<(), AppError> {
        self.conn.execute("COMMIT", [])
            .map_err(|e| AppError::Database(e.to_string()))?;
        self.committed = true;
        Ok(())
    }

    pub fn rollback(self) -> Result<(), AppError> {
        if !self.committed {
            self.conn.execute("ROLLBACK", [])?;
        }
        Ok(())
    }
}

impl<'a> Drop for Transaction<'a> {
    fn drop(&mut self) {
        if !self.committed {
            let _ = self.conn.execute("ROLLBACK", []);
        }
    }
}
```

### 8.4.2 UseCase 中的事务编排

```rust
// application/article_usecase.rs
impl ArticleUseCase {
    pub fn save_article_with_tags(
        &self,
        article: &Article,
        tags: &[Tag],
        client_version: u32,
    ) -> Result<Article, AppError> {
        let conn = self.pool.get()?;
        let tx = Transaction::begin(&conn)?;

        // 操作 1：更新文章（带乐观锁）
        let new_version = client_version + 1;
        let affected = conn.execute(
            "UPDATE articles
             SET title = ?1, content = ?2, version = ?3,
                 updated_at = datetime('now')
             WHERE id = ?4 AND version = ?5",
            params![article.title, article.content, new_version,
                    article.id, client_version],
        )?;

        if affected == 0 {
            return Err(AppError::VersionConflict {
                current_version: /* query */,
                client_version,
            });
        }

        // 操作 2：更新标签
        conn.execute(
            "DELETE FROM article_tags WHERE article_id = ?1",
            params![article.id],
        )?;
        for tag in tags {
            conn.execute(
                "INSERT INTO article_tags (article_id, tag_id) VALUES (?1, ?2)",
                params![article.id, tag.id],
            )?;
        }

        // 操作 3：更新项目统计
        conn.execute(
            "UPDATE projects SET article_count = (
                SELECT COUNT(*) FROM articles WHERE project_id = ?1
            ) WHERE id = ?1",
            params![article.project_id],
        )?;

        // 原子提交
        tx.commit()?;

        // 发射事件
        self.event_emitter.emit_entity_updated("article",
            &self.find_by_id(&conn, &article.id)?);

        self.find_by_id(&conn, &article.id)
    }
}
```

## 8.5 事务模式对比

| 模式             | 优点                   | 缺点                     | 适用场景           |
| ---------------- | ---------------------- | ------------------------ | ------------------ |
| 单操作事务       | 简单、无死锁风险       | 多操作需多次往返         | 简单 CRUD          |
| 多操作事务       | 原子性强               | 持锁时间长               | 级联更新           |
| 嵌套事务（SAVEPOINT）| 部分回滚            | 复杂度高                 | 批量导入           |
| 乐观锁事务       | 读不阻塞、无死锁       | 需要冲突处理             | 高频编辑（推荐）   |
| 悲观锁事务       | 强一致                 | 阻塞读、性能差           | 关键数据迁移       |

## 8.6 冲突解决流程

### 8.6.1 检测 → 提示 → 解决

```
用户 A 保存
  │ Rust 返回 VERSION_CONFLICT
  ▼
前端检测 conflict
  │
  ├─ 自动合并（无冲突字段）→ 重新保存
  │
  └─ 需手动解决 → 展示对比 UI
       │
       ├─ 用户选择：保留我的 / 采用对方 / 合并
       └─ 重新 invoke → 事务提交
```

## 8.7 事务监控与告警

```rust
// infrastructure/transaction_monitor.rs
use std::time::Instant;

pub struct TransactionMonitor {
    start: Instant,
    label: String,
    warn_threshold: Duration,
}

impl TransactionMonitor {
    pub fn new(label: &str) -> Self {
        Self {
            start: Instant::now(),
            label: label.to_string(),
            warn_threshold: Duration::from_millis(500),
        }
    }
}

impl Drop for TransactionMonitor {
    fn drop(&mut self) {
        let elapsed = self.start.elapsed();
        if elapsed > self.warn_threshold {
            tracing::warn!(
                "Slow transaction: {} took {:?}",
                self.label, elapsed
            );
        }
        if elapsed > Duration::from_secs(5) {
            tracing::error!(
                "Very slow transaction: {} took {:?}",
                self.label, elapsed
            );
        }
    }
}

    let _monitor = TransactionMonitor::new("save_article");
    // ... 事务逻辑
}
```

## 8.8 反模式与陷阱

| 反模式                                  | 后果                         |
| --------------------------------------- | ---------------------------- |
| 事务中执行 HTTP 请求或文件 I/O          | 长事务、锁超时、难以回滚     |
| 事务中发射 Event                        | Event 在 Rollback 后仍然发出 |
| 使用 `BEGIN` 而非 `BEGIN IMMEDIATE`     | 死锁风险（延迟锁）           |
| 事务跨越多个 await                      | 连接可能被回收               |
| 不检查 `affected == 0`                  | 乐观锁失效                   |
| 回滚后不发射 rollback event             | UI 不一致                    |
