# 09 — 离线缓存与冲突解决

## 9.1 背景与目标

MirageInk 是**本地优先**的桌面应用，天然离线可用。但未来若扩展为多设备协作，需要离线队列 + 冲突解决机制。本章设计为可逐步启用的架构，当前阶段以本地 SQLite 主数据为主。

## 9.2 数据分层

```
┌─────────────────────────────────────────────┐
│              数据存储分层                     │
│                                             │
│  L1 主数据 (SQLite)                         │
│    - 事务保证、权威数据                      │
│    - 所有写入须经过 Rust UseCase            │
│                                             │
│  L2 本地缓存 (IndexedDB / localStorage)     │
│    - 离线时临时存储未同步的变更              │
│    - Dirty Flag 标记待同步                  │
│    - 仅在离线期间使用                       │
│                                             │
│  L3 展示缓存 (RTK Store)                    │
│    - 窗口内存缓存                            │
│    - 窗口关闭即销毁                          │
└─────────────────────────────────────────────┘
```

### 9.3.2 离线检测

```typescript
// core/services/networkMonitor.ts
import { listen } from '@tauri-apps/api/event';
import { useStore } from 'react-redux';
import { setOnlineStatus } from '@/stores/appSlice';

export function useNetworkMonitor() {
  const store = useStore();

  useEffect(() => {
    // Tauri 没有直接的 online/offline 事件
    // 使用 navigator.onLine + 定时 health check
    const checkOnline = async () => {
      const online = navigator.onLine;
      if (online) {
        // 进一步确认：ping Rust health
        try {
          await invoke('health_check');
          store.dispatch(setOnlineStatus(true));
        } catch {
          store.dispatch(setOnlineStatus(false));
        }
      } else {
        store.dispatch(setOnlineStatus(false));
      }
    };

    const interval = setInterval(checkOnline, 10000);
    window.addEventListener('online', checkOnline);
    window.addEventListener('offline', () => store.dispatch(setOnlineStatus(false)));

    return () => {
      clearInterval(interval);
      window.removeEventListener('online', checkOnline);
      window.removeEventListener('offline', checkOnline);
    };
  }, [store]);
}
```

### 9.3.3 离线写入处理

```typescript
// view-models/offlineWriteHandler.ts
import { invoke } from '@tauri-apps/api/core';

export async function smartWrite<T>(
  command: string,
  params: Record<string, unknown>,
  optimisticPayload: T,
): Promise<T> {
  const isOnline = navigator.onLine;

  if (isOnline) {
    try {
      return await invoke<T>(command, params);
    } catch (error) {
      // 在线但失败：降级到离线队列
      await enqueueOfflineChange(command, params, optimisticPayload);
      return optimisticPayload;
    }
  } else {
    // 离线：存入队列
    await enqueueOfflineChange(command, params, optimisticPayload);
    return optimisticPayload;
  }
}

async function enqueueOfflineChange(
  command: string,
  params: Record<string, unknown>,
  payload: unknown,
) {
  await invoke('offline:enqueue', {
    change: {
      command,
      params: JSON.stringify(params),
      payload: JSON.stringify(payload),
      timestamp: new Date().toISOString(),
    },
  });
}
```

## 9.4 同步引擎

### 9.4.1 上线触发

```rust
// application/sync_engine.rs
pub struct SyncEngine {
    pool: Arc<Pool<SqliteConnectionManager>>,
    event_emitter: Arc<EventEmitter>,
}

impl SyncEngine {
    /// 网络恢复时调用
    pub async fn sync_pending_changes(&self) -> Result<Vec<SyncResult>, AppError> {
        let changes = self.load_pending_changes()?;
        let mut results = vec![];

        for change in changes {
            let result = self.apply_change(&change).await;
            match &result {
                SyncResult::Success => {
                    self.mark_synced(&change.id)?;
                }
                SyncResult::Conflict { .. } => {
                    self.mark_conflict(&change.id)?;
                }
                SyncResult::Failed { error } => {
                    self.increment_retry(&change.id)?;
                    if change.retry_count >= 3 {
                        self.mark_failed(&change.id)?;
                    }
                }
            }
            results.push(result);
        }

        // 同步完成后通知前端
        self.event_emitter.emit_sync_completed(&results);
        Ok(results)
    }
}
```

## 9.5 冲突解决策略

### 9.5.1 策略矩阵

| 策略              | 原理                                        | 适用场景             |
| ----------------- | ------------------------------------------- | -------------------- |
| Last Write Wins   | 以时间戳最新的为准                          | 标签、标题等简单字段 |
| 手动解决          | 展示差异，用户选择                          | 正文内容等关键数据   |
| 三路合并          | 基于共同祖先 (base) 合并分支修改            | 复杂文档             |
| 字段级合并        | 非冲突字段自动合并，冲突字段提示            | 结构化数据           |
| CRDT (未来)       | 无冲突复制数据类型，自动合并                 | 实时协作（远期）     |

### 9.5.2 当前实现：LWW + 手动

```rust
// infrastructure/conflict_resolver.rs
pub struct ConflictResolver;

impl ConflictResolver {
    /// 简单字段：Last Write Wins
    pub fn resolve_lww<T: Timestamped>(
        local: &T,
        remote: &T,
    ) -> T {
        if local.updated_at() >= remote.updated_at() {
            local.clone()
        } else {
            remote.clone()
        }
    }

    /// 核心内容：返回冲突信息供用户手动解决
    pub fn detect_content_conflict(
        local: &Article,
        remote: &Article,
        base: &Article,       // 共同祖先版本
    ) -> ConflictResolution {
        let mut resolution = ConflictResolution {
            auto_merged: remote.clone(),
            conflicts: vec![],
        };

        // 标题：LWW
        if local.updated_at >= remote.updated_at {
            resolution.auto_merged.title = local.title.clone();
        }

        // 内容：检测是否为真冲突
        if local.content != base.content && remote.content != base.content {
            // 双方都改了 → 真冲突
            resolution.conflicts.push(ConflictField {
                field: "content".into(),
                local_value: local.content.clone(),
                remote_value: remote.content.clone(),
                base_value: base.content.clone(),
                strategy: ConflictStrategy::ManualResolve,
            });
        } else if local.content != base.content {
            // 仅本地改了 → 用本地
            resolution.auto_merged.content = local.content.clone();
        }
        // else: 仅远程改了 → auto_merged 已用 remote

        resolution
    }
}
```

### 9.5.3 冲突解决 UI

```typescript
// components/ConflictResolveDialog.tsx
interface ConflictResolveProps {
  conflicts: SyncedConflict[];
  onResolveAll: (resolved: Map<string, ArticleDTO>) => void;
}

export const ConflictResolveDialog: React.FC<ConflictResolveProps> = ({
  conflicts, onResolveAll,
}) => {
  const [resolutions, setResolutions] = useState<Map<string, Resolution>>(new Map());

  const handleAutoMerge = () => {
    const merged = new Map<string, ArticleDTO>();
    conflicts.forEach(c => {
      // 简单字段 LWW，内容字段保留本地
      const resolved = {
        ...c.remote,
        title: c.local.updatedAt > c.remote.updatedAt ? c.local.title : c.remote.title,
        content: c.local.content,
      };
      merged.set(c.entityId, resolved);
    });
    onResolveAll(merged);
  };

  return (
    <Modal title={`${conflicts.length} 个冲突需要解决`}>
      {conflicts.map(conflict => (
        <ConflictCard key={conflict.entityId}>
          <DiffView
            local={conflict.local.content}
            remote={conflict.remote.content}
            base={conflict.base.content}
          />
          <Select
            value={resolutions.get(conflict.entityId)}
            onChange={(v) => setResolutions(m => new Map(m).set(conflict.entityId, v))}
          >
            <option value="local">保留本地</option>
            <option value="remote">采用远程</option>
            <option value="manual">手动编辑</option>
          </Select>
        </ConflictCard>
      ))}
      <Button onClick={handleAutoMerge}>自动合并</Button>
    </Modal>
  );
};
```

## 9.6 离线可用性矩阵

| 操作           | 离线可用 | 说明                     |
| -------------- | -------- | ------------------------ |
| 创建文章       | 是       | 存本地 SQLite + 队列     |
| 编辑文章       | 是       | 乐观更新 + 版本号递增    |
| 删除文章       | 是       | 软删除 (deleted_at)      |
| 查看文章列表   | 是       | 直接读本地 SQLite        |
| AI 写作         | 否       | 需 Python Agent + API    |
| AI 润色 (本地)  | 是       | Ollama 本地模型可用      |
| 搜索           | 是       | SQLite FTS5              |
| 导出           | 是       | 本地文件系统             |
| 同步到云端     | 否       | 需网络                   |

## 9.7 离线存储空间管理

```rust
// 离线队列大小限制
const MAX_OFFLINE_QUEUE_SIZE: usize = 500;      // 最多 500 条离线变更
const MAX_OFFLINE_STORAGE_MB: u64 = 50;          // 最多 50MB 离线数据
const MAX_OFFLINE_RETENTION_DAYS: i64 = 30;      // 离线变更保留 30 天

pub fn cleanup_offline_queue(conn: &Connection) -> Result<(), AppError> {
    // 删除 30 天前的离线记录
    conn.execute(
        "DELETE FROM offline_queue WHERE created_at < datetime('now', '-30 days')",
        [],
    )?;
    // 如果队列仍超过 500 条，删除最旧的 failed 记录
    conn.execute(
        "DELETE FROM offline_queue WHERE id IN (
            SELECT id FROM offline_queue
            WHERE status = 'failed'
            ORDER BY created_at ASC
            LIMIT max(0, (SELECT COUNT(*) FROM offline_queue) - 500)
        )",
        [],
    )?;
    Ok(())
}
```
