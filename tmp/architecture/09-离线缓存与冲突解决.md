# 09 — 离线缓存与冲突解决

## 9.1 背景与目标

MirageInk 是**本地优先**的桌面应用，天然离线可用。但未来若扩展为多设备协作，需要离线队列 + 冲突解决机制。本章设计为可逐步启用的架构，当前阶段以本地 SQLite 主数据为主。

## 9.2 数据分层

```
┌─────────────────────────────────────────────┐
│              数据存储分层                     │
│                                             │
│  L1 主数据 (SQLite)                         │
│    - 事务保证、权威数据                      │
│    - 所有写入须经过 Rust UseCase            │
│                                             │
│  L2 本地缓存 (IndexedDB / localStorage)     │
│    - 离线时临时存储未同步的变更              │
│    - Dirty Flag 标记待同步                  │
│    - 仅在离线期间使用                       │
│                                             │
│  L3 展示缓存 (RTK Store)                    │
│    - 窗口内存缓存                            │
│    - 窗口关闭即销毁                          │
└─────────────────────────────────────────────┘
```

```typescript
import { invoke } from '@tauri-apps/api/core';

export async function smartWrite<T>(
  command: string,
  params: Record<string, unknown>,
  optimisticPayload: T,
): Promise<T> {
  const isOnline = navigator.onLine;

  if (isOnline) {
    try {
      return await invoke<T>(command, params);
    } catch (error) {
      // 在线但失败：降级到离线队列
      await enqueueOfflineChange(command, params, optimisticPayload);
      return optimisticPayload;
    }
  } else {
    // 离线：存入队列
    await enqueueOfflineChange(command, params, optimisticPayload);
    return optimisticPayload;
  }
}

async function enqueueOfflineChange(
  command: string,
  params: Record<string, unknown>,
  payload: unknown,
) {
  await invoke('offline:enqueue', {
    change: {
      command,
      params: JSON.stringify(params),
      payload: JSON.stringify(payload),
      timestamp: new Date().toISOString(),
    },
  });
}
```

### 9.4.1 上线触发

```rust
// application/sync_engine.rs
pub struct SyncEngine {
    pool: Arc<Pool<SqliteConnectionManager>>,
    event_emitter: Arc<EventEmitter>,
}

impl SyncEngine {
    /// 网络恢复时调用
    pub async fn sync_pending_changes(&self) -> Result<Vec<SyncResult>, AppError> {
        let changes = self.load_pending_changes()?;
        let mut results = vec![];

        for change in changes {
            let result = self.apply_change(&change).await;
            match &result {
                SyncResult::Success => {
                    self.mark_synced(&change.id)?;
                }
                SyncResult::Conflict { .. } => {
                    self.mark_conflict(&change.id)?;
                }
                SyncResult::Failed { error } => {
                    self.increment_retry(&change.id)?;
                    if change.retry_count >= 3 {
                        self.mark_failed(&change.id)?;
                    }
                }
            }
            results.push(result);
        }

        // 同步完成后通知前端
        self.event_emitter.emit_sync_completed(&results);
        Ok(results)
    }
}
```

## 9.5 冲突解决策略

### 9.5.1 策略矩阵

| 策略              | 原理                                        | 适用场景             |
| ----------------- | ------------------------------------------- | -------------------- |
| **字段级 LWW**   | **每个字段独立比较时间戳，取最新**          | **默认策略（推荐）** |
| 手动解决          | 展示差异，用户选择                          | 正文内容等关键数据   |
| 三路合并          | 基于共同祖先 (base) 合并分支修改            | 复杂文档             |
| 字段级合并        | 非冲突字段自动合并，冲突字段提示            | 结构化数据           |
| CRDT (远期)       | 无冲突复制数据类型，自动合并                 | 实时协作（远期）     |

> **为什么不用整行 LWW？**
> 整行 LWW 会导致数据丢失：用户 A 修改标题，用户 B 同时修改标签。整行 LWW 会用最后一个写入者的整行数据覆盖，导致 A 的标题修改或 B 的标签修改丢失。
> 
> **字段级 LWW 解决方案**：每个字段独立比较 `updated_at`，仅覆盖有冲突的字段。

### 9.5.2 当前实现：字段级 LWW + 手动

```rust
// infrastructure/conflict_resolver.rs
pub struct ConflictResolver;

impl ConflictResolver {
    /// 字段级 LWW 解决
    /// 对每个字段独立比较时间戳，取最新版本
    pub fn resolve_field_level_lww(
        local: &Article,
        remote: &Article,
        base: &Article,
    ) -> Article {
        let mut merged = local.clone();
        
        // 对每个字段独立应用 LWW
        merged.title = Self::lww_field(
            local.title.clone(), local.updated_at,
            remote.title.clone(), remote.updated_at,
        );
        
        merged.content = Self::lww_field(
            local.content.clone(), local.updated_at,
            remote.content.clone(), remote.updated_at,
        );
        
        merged.tags = Self::lww_field(
            local.tags.clone(), local.updated_at,
            remote.tags.clone(), remote.updated_at,
        );
        
        // version 取最大值 + 1
        merged.version = std::cmp::max(local.version, remote.version) + 1;
        
        merged
    }
    
    /// 单个字段的 LWW 逻辑
    fn lww_field<T: Clone>(
        local_value: T,
        local_time: DateTime<Utc>,
        remote_value: T,
        remote_time: DateTime<Utc>,
    ) -> T {
        if local_time >= remote_time {
            local_value
        } else {
            remote_value
        }
    }
    
    /// 检测并标记需要手动解决的冲突
    pub fn detect_manual_conflicts(
        local: &Article,
        remote: &Article,
        base: &Article,
    ) -> Vec<ConflictField> {
        let mut conflicts = vec![];
        
        // 正文内容：若双方都修改了，标记为手动解决
        if local.content != base.content && remote.content != base.content {
            conflicts.push(ConflictField {
                field: "content".into(),
                local_value: serde_json::to_value(&local.content).unwrap(),
                remote_value: serde_json::to_value(&remote.content).unwrap(),
                base_value: serde_json::to_value(&base.content).unwrap(),
                strategy: ConflictStrategy::ManualResolve,
            });
        }
        
        conflicts
    }
    
    /// 完整冲突解决流程
    pub fn resolve(
        local: &Article,
        remote: &Article,
        base: &Article,
    ) -> ConflictResolution {
        // 1. 先应用字段级 LWW（自动合并无冲突字段）
        let mut auto_merged = Self::resolve_field_level_lww(local, remote, base);
        
        // 2. 检测需要手动解决的冲突
        let conflicts = Self::detect_manual_conflicts(local, remote, base);
        
        // 3. 对有冲突的字段，保留本地版本（等待用户决定）
        for conflict in &conflicts {
            match conflict.field.as_str() {
                "content" => {
                    // 保留本地版本，但标记冲突
                    auto_merged.content = local.content.clone();
                }
                _ => {}
            }
        }
        
        ConflictResolution {
            auto_merged,
            conflicts,
        }
    }
}
```

### 9.7.1 前端缓存淘汰策略

离线缓存不仅包含 SQLite 队列，还包含前端 localStorage/IndexedDB 中的领域数据快照。需防止前端存储无限膨胀。

#### 三层淘汰规则

| 层级 | 存储位置 | 淘汰策略 | 参数 |
|------|---------|---------|------|
| L1 热点数据 | Redux Store（内存） | 窗口关闭即释放 | — |
| L2 离线快照 | IndexedDB | LRU + max 50 篇 | 每篇 ~500KB，总计 ~25MB |
| L3 附件/图片 | IndexedDB / 文件系统 | TTL 7 天 + max 100MB | 单文件 max 10MB |

```typescript
// services/cacheManager.ts
interface CacheEntry<T> {
  key: string;
  data: T;
  size: number;          // 字节
  lastAccess: number;    // 时间戳
  createdAt: number;
}

class IndexedDBCache {
  private maxSize = 25 * 1024 * 1024;   // 25 MB
  private maxEntries = 50;
  private db: IDBDatabase | null = null;

  async set<T>(key: string, data: T): Promise<void> {
    await this.ensureEviction();
    
    const entry: CacheEntry<T> = {
      key, data,
      size: new TextEncoder().encode(JSON.stringify(data)).length,
      lastAccess: Date.now(),
      createdAt: Date.now(),
    };
    
    const tx = (await this.getDB()).transaction('cache', 'readwrite');
    tx.objectStore('cache').put(entry);
  }

  private async ensureEviction(): Promise<void> {
    const entries = await this.getAllEntries();
    let totalSize = entries.reduce((sum, e) => sum + e.size, 0);
    
    // 策略 1：按条目数淘汰（LRU：删除最久未访问的）
    if (entries.length >= this.maxEntries) {
      const sorted = entries.sort((a, b) => a.lastAccess - b.lastAccess);
      const toEvict = sorted.slice(0, entries.length - this.maxEntries + 1);
      await this.deleteBatch(toEvict.map(e => e.key));
    }
    
    // 策略 2：按总大小淘汰
    while (totalSize > this.maxSize && entries.length > 0) {
      const oldest = entries.sort((a, b) => a.lastAccess - b.lastAccess)[0];
      await this.delete(oldest.key);
      entries.splice(entries.indexOf(oldest), 1);
      totalSize = entries.reduce((sum, e) => sum + e.size, 0);
    }
  }

  // 资源附件 TTL 清理
  async cleanExpiredAttachments(ttlDays = 7): Promise<void> {
    const cutoff = Date.now() - ttlDays * 86400 * 1000;
    const tx = (await this.getDB()).transaction('attachments', 'readwrite');
    const store = tx.objectStore('attachments');
    
    const cursor = store.openCursor();
    cursor.onsuccess = (event) => {
      const c = (event.target as IDBRequest).result;
      if (c && c.value.createdAt < cutoff) {
        c.delete();
        c.continue();
      }
    };
  }
```

```rust
    let deleted_queue = conn.execute(

         WHERE (status = 'synced' AND synced_at < datetime('now', '-3 days'))
            OR (status = 'failed' AND created_at < datetime('now', '-30 days'))
            OR (status = 'cancelled' AND created_at < datetime('now', '-1 day'))",
        [],
    )?;

    // 2. 清理已解决的冲突记录

        "DELETE FROM conflict_records WHERE resolved_at < datetime('now', '-7 days')",
        [],
    )?;
    report.deleted_conflicts = deleted_conflicts;
    
    // 3. VACUUM 回收空间（仅在删除大量数据后执行）
    if deleted_queue + deleted_conflicts > 100 {
```

## 9.8 离线队列完整生命周期

一条离线变更从产生到落库的完整路径：

```
用户操作 → 前端立即 UI 更新
  │
  ├─ [在线] → invoke → Rust 事务 → SQLite → emit 事件
  │
  └─ [离线] → 入队（IndexedDB + SQLite 离线表）
       │
       ├─ 网络恢复 → 同步引擎读取队列
       │    ├─ 按 FIFO 顺序发送
       │    ├─ 每条变更带 client_timestamp 和 client_version
       │    └─ 逐条等待 Rust 响应
       │
       ├─ [响应: 成功] → 标记 synced → 保留 3 天（用于冲突排查）
       ├─ [响应: VERSION_CONFLICT] → 标记 conflict → 触发 9.5 冲突解决
       ├─ [响应: 网络错误] → 保留 → 下次同步重试
       └─ [响应: 其他错误] → 重试 3 次 → 标记 failed → 30 天后清理
       
幂等性保证：
  - 每条队列项有唯一 client_id (UUID v7，时间排序)
  - Rust 侧记录最近 1000 条已处理 client_id
  - 重复 client_id → 返回 "already_processed"（不报错）
```

### 9.8.1 幂等性实现

```rust
// infrastructure/idempotency.rs
use std::collections::HashSet;
use std::sync::Mutex;
use lru::LruCache;
use std::num::NonZeroUsize;

/// 最近已处理的客户端请求 ID 缓存（防止离线队列重复消费）
static PROCESSED_IDS: Lazy<Mutex<LruCache<String, ()>>> =
    Lazy::new(|| Mutex::new(LruCache::new(NonZeroUsize::new(1000).unwrap())));

pub fn check_and_mark_idempotent(client_id: &str) -> bool {
    let mut cache = PROCESSED_IDS.lock().unwrap();
    if cache.contains(client_id) {
        return false; // 已处理过
    }
    cache.put(client_id.to_string(), ());
    true
}
```

```typescript
  status: 'pending' | 'syncing' | 'synced' | 'conflict' | 'failed';
}

function createQueuedChange(
  entityType: string, entityId: string,
  action: string, payload: unknown
): QueuedChange {
  return {
    client_id: uuidv7(),
    entity_type: entityType,
    entity_id: entityId,
    action,
    payload,
    client_timestamp: Date.now(),
    client_version: 0, // 由调用方设置
    created_at: new Date().toISOString(),
    retries: 0,
    status: 'pending',
  };
}
```
