# 04 — 事件系统与跨窗口通信

## 4.1 通信体系总览

```
┌───────────────────────────────────────────┐
│              Tauri Event System            │
│                                           │
│  ┌─────────┐  emit   ┌─────────┐         │
│  │  Rust    │ ──────► │ Window A│ listen  │
│  │ Backend  │ ──────► │ Window B│ listen  │
│  │          │ ──────► │ Window C│ listen  │
│  └────┬─────┘         └─────────┘         │
│       │                                    │
│       │ invoke (request/response)          │
│       ▼                                    │
│  ┌─────────┐  emit_and_wait  ┌─────────┐  │
│  │ Window A│ ◄──────────────►│ Window B│  │
│  └─────────┘    (via Rust)   └─────────┘  │
└───────────────────────────────────────────┘
```

| 模式           | 方向             | 协议        | 场景                       |
| -------------- | ---------------- | ----------- | -------------------------- |
| IPC Command    | Window → Rust    | invoke      | 数据 CRUD、业务操作        |
| Global Event   | Rust → All Windows| emit/listen | 领域数据变更广播           |
| Window Event   | Rust → Target Win| emit_to     | 定向通知（状态、错误）      |
| RPC            | Window ↔ Window  | invoke+reply| 模态窗口交互               |
| Bridge Event   | Rust ↔ Python    | HTTP + Auth Token | AI Agent 上下文回读、回调通知（详见 05） |
### 4.2.5 事件协议执行细则

> **本节约定义执行细则**，包括事件生命周期管理、Payload 结构约定、事件冲突解决等。完整团队协作规范详见 [13-团队协作与开发规范.md](./13-团队协作与开发规范.md) §13.3。

**事件新增流程**（PR 必查）：

1. 确认事件名在 §4.2.4 事件目录中不存在
2. 在 PR 描述中勾选 13 §13.3.1 的新增事件检查清单
3. 更新 §4.2.4 事件目录（PR 必须包含文档更新）
4. 确保 Payload 符合 13 §13.3.2 标准结构

**事件弃用流程**：

1. 在事件名后加 `@deprecated` 注释
2. 在 §4.2.4 事件目录中标注弃用版本和计划删除版本
3. 保留 2 个版本（约 1 个月）后删除

## 4.2 事件命名规范

## 4.3 Rust 侧事件发射

### 4.3.1 EventEmitter 模块

```rust
// events/emitter.rs
use tauri::{AppHandle, Emitter};
use std::sync::Arc;

pub struct EventEmitter {
    app: AppHandle,
}

impl EventEmitter {
    pub fn new(app: AppHandle) -> Self {
        Self { app }
    }

    /// 发射领域变更事件到所有窗口
    pub fn emit_entity_updated<T: Serialize>(
        &self,
        entity_type: &str,
        payload: &T,
    ) {
        let event_name = format!("{entity_type}:{entity_type}:updated");
        let _ = self.app.emit(&event_name, payload);
    }

    /// 定向发送到指定窗口
    pub fn emit_to_window<T: Serialize>(
        &self,
        window_label: &str,
        event: &str,
        payload: &T,
    ) -> Result<(), AppError> {
        if let Some(window) = self.app.get_webview_window(window_label) {
            window.emit(event, payload)?;
        }
        Ok(())
    }
}
```

### 4.3.2 去重发射器

```rust
// events/dedup_emitter.rs
use std::collections::HashSet;
use std::sync::Mutex;
use std::time::{Duration, Instant};
use std::collections::hash_map::DefaultHasher;
use std::hash::{Hash, Hasher};

type EventKey = (String, u64);

static RECENT_EVENTS: Lazy<Mutex<HashSet<EventKey>>> =
    Lazy::new(|| Mutex::new(HashSet::new()));

const DEDUP_WINDOW_MS: u64 = 300;

pub fn emit_deduped<T: Serialize>(
    app: &AppHandle,
    event: &str,
    payload: &T,
) {
    let json = serde_json::to_string(payload).unwrap_or_default();
    let mut hasher = DefaultHasher::new();
    json.hash(&mut hasher);
    let hash = hasher.finish();

    let key: EventKey = (event.to_string(), hash);
    let mut recent = RECENT_EVENTS.lock().unwrap();

    if recent.contains(&key) {
        return; // 去重：300ms 内相同内容已发送过
    }

    recent.insert(key.clone());
    let _ = app.emit(event, &json);

    // 300ms 后自动清理，防止内存无限增长
    let key_clone = key.clone();
    std::thread::spawn(move || {
        std::thread::sleep(Duration::from_millis(DEDUP_WINDOW_MS));
        RECENT_EVENTS.lock().unwrap().remove(&key_clone);
    });
}
```

**并发安全说明**：
- `Mutex<HashSet>` 保护共享状态
- 每个清理任务在独立线程执行，不阻塞 emit
- `lazy_static` 确保全局唯一实例
- 极端并发下（>1000 emit/s），HashSet 锁竞争可接受（纳秒级）

## 4.4 事件分级

| 级别 | 频率       | 策略                | 示例              |
| ---- | ---------- | ------------------- | ----------------- |
| L1   | < 1/秒     | 即时 emit + 去重    | CRUD、重命名      |
| L2   | 1-10/秒    | Debounce 100ms + 去重| 批量导入进度       |
| L3   | > 10/秒    | 仅窗口内，不广播    | 打字、拖拽、滚动  |

## 4.5 前端事件监听

### 4.5.1 领域事件监听器

```typescript
// core/services/eventListener.ts
import { listen, UnlistenFn } from '@tauri-apps/api/event';
import type { ArticleDTO, ProjectDTO } from '@/modules/domain';

type EventHandler<T> = (payload: T) => void;

class EventListenerService {
  private unlisteners: UnlistenFn[] = [];

  /// 注册领域事件监听，自动 dispatch 到 Store
  listenToDomainEvents(
    store: AppStore,              // 窗口本地 Store
    windowLabel: string
  ): UnlistenFn[] {
    const handlers: Array<[string, EventHandler<any>]> = [
      [
        'article:article:updated',
        (p: ArticleDTO) => store.dispatch(articleUpserted(p)),
      ],
      [
        'article:article:created',
        (p: ArticleDTO) => store.dispatch(articleUpserted(p)),
      ],
      [
        'article:article:deleted',
        (p: { id: string }) => store.dispatch(articleDeleted(p.id)),
      ],
      [
        'project:project:updated',
        (p: ProjectDTO) => store.dispatch(projectUpserted(p)),
      ],
      [
        'config:theme:changed:all',
        (p: { theme: string }) => store.dispatch(themeChanged(p.theme)),
      ],
    ];

    // 异步注册所有监听
    const unlisteners = handlers.map(([event, handler]) => {
      const unlisten = listen(event, (e) => handler(e.payload));
      return async () => (await unlisten)();
    });

    this.unlisteners.push(...unlisteners);
    return unlisteners;
  }

  /// 窗口卸载时清理
  async destroy() {
    await Promise.all(this.unlisteners.map(fn => fn()));
    this.unlisteners = [];
  }
}

export const eventListenerService = new EventListenerService();
```

// core/services/debouncedListener.ts
import { debounce } from 'lodash';

export function createDebouncedListener<T>(
  event: string,
  handler: (payload: T) => void,
  waitMs: number = 100,
): UnlistenFn {
  const debounced = debounce(handler, waitMs, {
    leading: false,
    trailing: true,
  });

  return listen<T>(event, (e) => debounced(e.payload));
}

## 4.6 跨窗口 RPC

### 4.6.1 架构

```
Window A (caller)
  │ invoke('rpc:call', { target: 'Window B', method, params })
  ▼
Rust RPC Router
  ├─ 解析 target
  ├─ 权限校验
  ├─ emit_and_wait → Window B
  └─ reply → Window A
```

### 4.6.2 Rust 实现

```rust
// commands/rpc_commands.rs
use std::collections::HashMap;
use tauri::Emitter;

#[tauri::command]
async fn rpc_call(
    app: AppHandle,
    target: String,
    method: String,
    params: serde_json::Value,
) -> Result<serde_json::Value, String> {
    // 超时 30s
    let timeout = Duration::from_secs(30);

    // 生成请求 ID
    let request_id = uuid::Uuid::new_v4().to_string();
    let request_payload = serde_json::json!({
        "request_id": request_id,
        "method": method,
        "params": params,
    });

    // 发送到目标窗口
    let target_window = app.get_webview_window(&target)
        .ok_or("Target window not found")?;

    // 使用 oneshot channel 等待回复
    let (tx, rx) = tokio::sync::oneshot::channel();

    // 注册临时回复监听
    let app_clone = app.clone();
    let request_id_clone = request_id.clone();
    let unlisten = app.listen_global(
        format!("rpc:reply:{request_id}"),
        move |event| {
            let _ = tx.send(event.payload().to_string());
        },
    );

    target_window.emit("rpc:request", &request_payload)
        .map_err(|e| e.to_string())?;

    // 等待回复或超时
    let result = tokio::time::timeout(timeout, rx).await
        .map_err(|_| "RPC timeout")?
        .map_err(|_| "RPC channel closed")?;

    // 清理临时监听
    app_clone.unlisten(unlisten);

    Ok(serde_json::from_str(&result).unwrap_or_default())
}
```

## 4.7 事件可靠性保证

| 保障             | 机制                                       |
| ---------------- | ------------------------------------------ |
| 去重             | 300ms 窗口 + 内容哈希                      |
| 防抖             | 前端 100ms debounce                        |
| 有序性           | Tauri Event 底层保证 FIFO                   |
| 遗漏检测         | 窗口聚焦时触发全量同步（增量基于 version） |
| 异常恢复         | 监听器断连时自动重连（指数退避）           |
| 内存控制         | 去重 HashSet 300ms 自动清理                |

## 4.8 故障模式

| 故障               | 影响                   | 处理                       |
| ------------------ | ---------------------- | -------------------------- |
| 事件 lost（极罕见） | 窗口数据不一致         | 聚焦时全量同步 + version diff / 每 30s 增量轮询兜底 |
| 事件重复（已去重）  | 浪费 dispatch          | 去重机制覆盖               |
| RPC 超时            | 模态窗口卡住           | 30s 超时 + 错误提示        |
| 目标窗口不存在       | RPC 失败               | 返回明确错误               |
| 监听器意外断连       | 窗口漏收事件           | Rust 侧 `AppHandle::listen_global` 自动重连；前端 `on_window_event` 监控重连 |
| Bridge Auth 失败     | Python 回调被拒        | 窗口收到 `bridge:auth-error`，提示用户重启 Agent（详见 05/06） |

## 4.9 事件重放与恢复机制

当窗口因网络抖动、挂起到后台、或监听器断连而漏收事件时，系统通过三级恢复机制补回缺失的状态。

### 恢复层次

| 层级 | 触发条件 | 机制 | 延迟 |
|------|---------|------|------|
| L1 增量轮询 | 每 30s 定时 | 对比本地 `last_sync_version` 与 Rust 当前 version | < 100ms |
| L2 聚焦恢复 | 窗口获得焦点 | `window.onFocusChanged` → 全量 version diff | < 500ms |
| L3 事件重放 | 断连恢复后 | 从 Rust replay buffer 回放未消费事件 | < 1s |

### 4.9.1 事件重放缓冲区

```rust
// events/replay_buffer.rs
use std::collections::VecDeque;
use std::sync::Mutex;
use std::time::{Duration, Instant};

/// 最近 N 条事件的环形缓冲区（支持窗口断连恢复）
pub struct EventReplayBuffer {
    buffer: Mutex<VecDeque<ReplayEntry>>,
    max_entries: usize,
    max_age: Duration,
}

struct ReplayEntry {
    event_name: String,
    payload: String,         // JSON
    timestamp: Instant,
    sequence_id: u64,        // 全局递增序号
}

impl EventReplayBuffer {
    pub fn new(max_entries: usize, max_age_secs: u64) -> Self {
        Self {
            buffer: Mutex::new(VecDeque::new()),
            max_entries,
            max_age: Duration::from_secs(max_age_secs),
        }
    }
    
    /// 记录事件到重放缓冲区
    pub fn record(&self, event_name: &str, payload: &str) -> u64 {
        let mut buf = self.buffer.lock().unwrap();
        let seq = buf.back().map(|e| e.sequence_id + 1).unwrap_or(1);
        
        buf.push_back(ReplayEntry {
            event_name: event_name.to_string(),
            payload: payload.to_string(),
            timestamp: Instant::now(),
            sequence_id: seq,
        });
        
        // 淘汰过期或超量条目
        let cutoff = Instant::now() - self.max_age;
        while buf.front().map(|e| e.timestamp < cutoff).unwrap_or(false) {
            buf.pop_front();
        }
        while buf.len() > self.max_entries {
            buf.pop_front();
        }
        
        seq
    }
    
    /// 获取从 last_seq 之后的所有事件
    pub fn replay_from(&self, last_seq: u64) -> Vec<ReplayPayload> {
        let buf = self.buffer.lock().unwrap();
        buf.iter()
            .filter(|e| e.sequence_id > last_seq)
            .map(|e| ReplayPayload {
                event_name: e.event_name.clone(),
                payload: e.payload.clone(),
                sequence_id: e.sequence_id,
            })
            .collect()
    }
}

#[derive(Serialize)]
pub struct ReplayPayload {
    pub event_name: String,
    pub payload: String,
    pub sequence_id: u64,
}
```

### 4.9.2 前端重放消费

```typescript
// core/services/eventReplay.ts
import { invoke } from '@tauri-apps/api/core';

class EventReplayService {
  private lastSeq: number = 0;
  private replaying = false;

  /// 窗口聚焦时触发恢复
  async onWindowFocused() {
    if (this.replaying) return;
    this.replaying = true;
    
    try {
      // 1. 请求增量重放
      const events = await invoke<ReplayPayload[]>('event:replay', {
        last_sequence: this.lastSeq,
      });
      
      // 2. 按序分发到 Store
      for (const event of events) {
        this.dispatchToStore(event);
        this.lastSeq = Math.max(this.lastSeq, event.sequence_id);
      }
      
      // 3. 补充全量版本 diff（对比本地与远程 version 差异）
      await this.fullVersionDiff();
      
      console.log(`[EventReplay] Replayed ${events.length} events, seq=${this.lastSeq}`);
    } catch (e) {
      console.error('[EventReplay] Replay failed:', e);
    } finally {
      this.replaying = false;
    }
  }

  private async fullVersionDiff() {
    // 获取本地缓存的所有 entity version
    // 对比 Rust 侧版本 → 发现 gap → 拉取缺失数据
    const store = window.__REDUX_STORE__;
    const state = store.getState();
    
    const localVersions: Record<string, number> = {};
    for (const [id, article] of Object.entries(state.articles.items)) {
      localVersions[id] = (article as any).version;
    }
    
    const staleIds = await invoke<string[]>('sync:version_diff', {
      versions: localVersions,
    });
    
    if (staleIds.length > 0) {
      const freshData = await invoke<Record<string, unknown>>('sync:fetch_batch', {
        ids: staleIds,
      });
      for (const [id, entity] of Object.entries(freshData)) {
        store.dispatch({ type: 'article/upserted', payload: entity });
      }
      console.log(`[EventReplay] Synced ${staleIds.length} stale entities`);
    }
  }

  private dispatchToStore(event: ReplayPayload) {
    // 对事件执行与 listen() 相同的 dispatch 逻辑（见 4.5.1）
    const store = window.__REDUX_STORE__;
    const handlers: Record<string, (payload: unknown) => void> = {
      'article:article:updated': (p) => store.dispatch({ type: 'article/upserted', payload: p }),
      'article:article:created': (p) => store.dispatch({ type: 'article/upserted', payload: p }),
      'article:article:deleted': (p) => store.dispatch({ type: 'article/deleted', payload: (p as any).id }),
      'project:project:updated': (p) => store.dispatch({ type: 'project/upserted', payload: p }),
    };
    
    const handler = handlers[event.event_name];
    if (handler) {
      handler(JSON.parse(event.payload));
    }
  }
}

export const eventReplayService = new EventReplayService();
```

## 4.10 最终一致性校验

多窗口场景下，即使事件机制正常运行，极端情况下仍可能出现窗口间数据漂移。定期一致性校验作为最后防线。

### 4.10.1 跨窗口 Version Gap 检测

```rust
// sync/consistency_checker.rs
use std::collections::HashMap;

pub struct ConsistencyChecker {
    pool: Arc<r2d2::Pool<SqliteConnectionManager>>,
}

impl ConsistencyChecker {
    /// 对比窗口提交的本地版本快照与数据库实际版本
    pub fn check_version_gap(
        &self,
        window_label: &str,
        local_snapshot: &HashMap<String, u64>,
    ) -> Vec<VersionGap> {
        let conn = self.pool.get().unwrap();
        let mut gaps = vec![];
        
        let mut stmt = conn.prepare(
            "SELECT id, version FROM articles WHERE id IN (?)"
        ).unwrap();
        
        for (entity_id, &local_version) in local_snapshot {
            let db_version: u64 = conn.query_row(
                "SELECT version FROM articles WHERE id = ?1",
                params![entity_id],
                |row| row.get(0),
            ).unwrap_or(0);
            
            if db_version > local_version {
                gaps.push(VersionGap {
                    entity_id: entity_id.clone(),
                    local_version,
                    db_version,
                    gap: db_version - local_version,
                });
            }
        }
        
        if !gaps.is_empty() {
            tracing::warn!(
                "Window {window_label}: {} version gaps detected, max gap={}",
                gaps.len(),
                gaps.iter().map(|g| g.gap).max().unwrap_or(0)
            );
        }
        
        gaps
    }
    
    /// 自动修复：将缺失的变更推送给窗口
    pub fn auto_fix(&self, gaps: &[VersionGap]) -> Vec<ArticleDTO> {
        let conn = self.pool.get().unwrap();
        gaps.iter()
            .filter_map(|g| {
                let article = conn.query_row(
                    "SELECT * FROM articles WHERE id = ?1",
                    params![g.entity_id],
                    |row| Ok(Article::from_row(row)),
                ).ok()?;
                Some(ArticleDTO::from(article))
            })
            .collect()
    }
}

struct VersionGap {
    entity_id: String,
    local_version: u64,
    db_version: u64,
    gap: u64,
}
```

### 4.10.2 一致性校验触发时机

| 触发时机 | 间隔 | 范围 |
|---------|------|------|
| 窗口聚焦 | 每次 | 当前窗口打开的文章 + 项目列表 |
| 定时巡检 | 每 5 分钟 | 全部 entity 的 version 对比 |
| 保存前 | 每次 | 仅当前编辑的 entity |
| 手动触发 | — | 开发者面板"检查一致性"按钮 |

> **设计原则**：一致性校验不阻塞用户操作（仅记录 gap，异步修复），version diff 增量传输（仅返回 ID 列表，不传全量数据），网络开销 < 1KB/次。
